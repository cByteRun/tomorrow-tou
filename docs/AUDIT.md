## Что установлено по сбоям входа

Сообщение `Bind for 127.0.0.1:8080 failed: port is already allocated` подтверждает, что новый контейнер API не стартовал на занятом host-порту. JavaFX мог обращаться к другому/старому серверу. Теперь порт общий (18080 / API_PORT), health идентифицирует TomorrowTOU и готовность после инициализации; frontend проверяет адрес перед открытием окна. Это не доказывает причину каждого последующего отказа.

В проверке BCrypt нет минутной блокировки. Для всех четырёх ролей выполнены три цикла: успешный вход → неверный пароль → немедленный правильный вход → доступ к профилю. Хэш пароля не менялся. Проверены отзыв/истечение токена, отключение аккаунта, ошибка сервиса 500 и различие неверного пароля/роли. Это HTTP-проверки настоящих контроллеров/security с тестовыми репозиториями, не доступ к пользовательской БД.

Исправлены риски GUI: второй вход во время первого, изменение формы/роли в полёте, очистка пароля после отказа; preferences теперь используют отправленный снимок формы. Login не отправляет старый токен. До готовности API возвращается 503 вместо ошибки учётных данных. Неверный пароль — 401, неверная роль при правильном пароле — отдельный 403.

Audit LOGIN_FAILED различает ACCOUNT_NOT_FOUND, ACCOUNT_DISABLED, PASSWORD_MISMATCH; роль отражается отдельным описанием. Пароли/токены не записываются. Аудит доступен администратору и в `/app/logs/audit.log` контейнера. Демонстрационные аккаунты создаются только при пустой таблице пользователей; изменение DEMO_PASSWORD не сбрасывает сохранённые пароли. БД и чужие сервисы не удалялись.

## Что проверено в welcome

Font-тесты читают реальные TTF и полный русский алфавит; narrative-тесты проходят преподавательские этапы, шесть студенческих циклов и перезапуск. Исходники содержат AnimationTimer, этапы 2,4 с, движение карточки/орбиты/пакетов/QR, раскрытие строки, пульсацию календаря, плавную прокрутку и изменение фона, паузу и reduced-motion.

Эти проверки не подтверждают траектории, перспективу, размеры, веса JavaFX-шрифтов, hover/focus и плавность 1:1. Для этого нужны работающий дисплей и сравнение с финальным `prototype/welcome.html`, включая JavaScript-изменения. Реальная биометрия/Bluetooth не входят в объём ТЗ.

## Полная сквозная приёмка

Запуск в обычном окружении с Docker, Maven Central и DISPLAY/Xvfb:

```sh
./scripts/build.sh
./scripts/e2e-test.sh
```

PostgresApiIT использует отдельный PostgreSQL 16 Testcontainer с настоящей миграцией. WelcomeE2EIT использует настоящий JavaFX/FXML, ApiClient и запущенный Compose API: ошибочный ручной вход → немедленное исправление → кабинет → Dashboard → навигация → профиль → выход/отзыв. Отсутствие GUI не превращается в успешный пропуск. UI E2E не удаляет пользовательские записи; пароль демонстрационного набора должен соответствовать README.

Ручные сценарии дополняют автоматические и закрывают checklist M1–M6:

1. UC-01/UC-10: всеми ролями войти вручную, исправить ошибочный пароль без ожидания, переключить показ пароля, открыть профиль, выйти, проверить старый токен. Welcome сравнить в 1440×900: все три секции, разделитель, шрифты, этапы и пауза анимации.
2. UC-03–UC-05: администратор создаёт дисциплину, назначает преподавателю/группе, добавляет студента; проверяет карточки, кураторство, нагрузку, поиск/фильтры/сортировку/страницы. Отказ от удаления оставляет запись неизменной.
3. UC-06: назначить занятие; отклонить пересечение преподавателя и аудитории, принять соседний интервал, сопоставить календарь/таблицу, подтвердить отмену.
4. UC-07/UC-08: преподаватель ведёт журнал своего занятия, меняет оценку и посещаемость; проверяет валидацию и пересчёт средних. Студент видит только свои оценки. Прямые запросы и экспорт не раскрывают чужие данные.
5. U-04: сотрудник просматривает нагрузку/занятия преподавателя и создаёт проверку; не получает право менять чужую проверку, оценки, посещаемость или пользователей.
6. UC-02/UC-09: изменения в БД отражаются в Dashboard; XLSX/DOCX открываются в офисном редакторе и совпадают с журналами/фильтрами.
7. NFR-03/NFR-05/NFR-06: перезапуск сохраняет данные, отклонённая операция не сохраняется частично, app/error/audit содержат соответствующие события без секретов.
