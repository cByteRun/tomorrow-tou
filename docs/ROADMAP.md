# Roadmap реализации требований

**Текущий фокус:** закрыть сквозную приёмку MVP: повторный ручной вход всеми ролями, PostgreSQL-операции, реальные POI-документы и визуальный welcome 1:1. Наличие кода не заменяет эти проверки.

Основание — [REQUIREMENTS.md](REQUIREMENTS.md), выведенный из [TZ.md](TZ.md). Этапы бывшего DEVELOPMENT.md перенесены в milestones ниже. `[x]` — указанная бизнес-фича реализована в исходниках либо указанная проверка реально выполнена; `[ ]` — конкретный результат ещё не достигнут. Состояние проверок: [AUDIT.md](AUDIT.md). Соответствие модулям: [ARCHITECTURE.md](ARCHITECTURE.md).

## Фаза 1 — MVP: обязательный объём ТЗ

### M1 — Основание системы и университетские данные

Зависимости: начало проекта. Требования: NFR-01–NFR-05, NFR-11; U-01, U-02. Этапы реализации: анализ ТЗ, Maven-модули, доменная модель, Flyway/ORM, инфраструктура.

- [x] Домен учебного плана: дисциплины и семестры, связи преподавателей и групп с дисциплинами.
- [x] Домен университета: студенты, преподаватели, группы, аудитории; все 10 сущностей ТЗ, 1:N и N:M, ограничения.
- [x] Разделение frontend/backend и feature packages; native JavaFX/FXML, Spring Boot Service Layer и JPA.
- [x] PostgreSQL/API/Adminer Compose, JDK 21/Maven, mvnw и скрипты.
- [x] Схема данных и DBML согласованы по таблицам, колонкам и связям с Flyway V1.
- [ ] PostgreSQL стартует в Docker, Flyway применяет миграцию, Hibernate validate проходит, данные сохраняются после перезапуска — подтверждено выполнением.

### M2 — Доступ, профиль и главное окно

Зависимости: M1. Требования: FR-01, FR-11, FR-18; NFR-06, NFR-10; UC-01, UC-10; U-03, U-05. Этапы: Spring Security/сеансы, welcome и кабинет, повторный аудит входа.

- [x] Домен доступа: четыре роли, вход в свой кабинет, профиль, выход и отзыв сеанса.
- [x] Главное окно и доступная роли навигация.
- [x] Вход не пересекается со вторым запросом; пароль после ошибки сохраняется; новый вход не использует старый bearer token.
- [x] Общий порт API 18080 / API_PORT, идентификация и ожидание готовности нужного сервера.
- [x] Welcome: три секции, роль/логин/пароль, разделитель, шрифты и непрерывные анимации по прототипу.
- [x] HTTP-регрессии повторного входа всеми ролями: неверный пароль → немедленный корректный вход, без минутного ожидания.
- [ ] Непостоянный отказ ручного входа на пользовательской БД воспроизведён и причина подтверждена либо проверено его устранение.
- [ ] Native JavaFX E2E проходит для всех четырёх ролей на настоящем API/PostgreSQL.
- [ ] Welcome принят сравнением с окончательным HTML, включая размеры, шрифтовые веса, перспективу и плавность 1:1.

### M3 — Справочники и связанные карточки

Зависимости: M1, M2. Требования: FR-03–FR-05, FR-12–FR-15, FR-17; UC-03–UC-05. Этапы: транзакционные CRUD, таблицы, формы, карточки, поиск/фильтры.

- [x] Домен студентов: CRUD, карточка, обязательные поля и связи с группой.
- [x] Домен преподавателей: свои дисциплины, расписание и нагрузка.
- [x] Домен групп: состав, дисциплины и куратор.
- [x] Таблицы с поиском, фильтрами, сортировкой и страницами по 10 по разумно загруженному доступному набору.
- [x] Формы/понятные ошибки; подтверждение удаления и применимых опасных действий.
- [ ] Сквозное создание → просмотр карточки → изменение → подтверждённое удаление и отказ от удаления проверены на настоящей БД через GUI.

### M4 — Расписание и учебные журналы

Зависимости: M3. Требования: FR-06–FR-09, FR-13–FR-16; NFR-05; UC-06–UC-08. Этапы: бизнес-правила расписания, посещаемость/оценки, транзакции и аудит.

- [x] Домен расписания: календарь/таблица, назначения, отмена, конфликты преподавателя и аудитории.
- [x] Домен посещаемости: отметки по занятию, индивидуальные и массовые операции.
- [x] Домен оценок: выставление/редактирование, средние студента, группы и дисциплины.
- [x] Ограничение студента собственными оценками и преподавателя своими дисциплинами проверяется сервером.
- [x] Содержательные unit-тесты конфликтов, оценок, прав и сервисных запретов выполнены.
- [ ] PostgreSQL IT подтверждают конфликты, связи журналов, права и сохранение/откат операций; GUI-проверка подтверждает отображение результата.

### M5 — Dashboard, отчёты и контроль преподавателей

Зависимости: M4. Требования: FR-02, FR-10; NFR-06, NFR-07, NFR-10; UC-02, UC-09; U-04. Этапы: агрегаты Dashboard, Apache POI, supervision, аудит.

- [x] Домен аналитики: статистика БД, занятия сегодня, средние, KPI и две диаграммы.
- [x] Домен отчётов: XLSX-ведомость и DOCX-справка из разрешённых данных через POI.
- [x] Домен контроля преподавателей: сотрудник просматривает нагрузку/занятия, создаёт проверку и замечание; администратор остаётся отдельной ролью (U-04).
- [x] Log4j 2: технические логи, ошибки и аудит; сервер не пишет пароли и токены.
- [ ] Полная компиляция backend с POI и шесть POI unit-тестов успешно выполнены.
- [ ] Выгруженные XLSX/DOCX открываются, совпадают с данными БД и соблюдают RBAC; Dashboard пересчитывается после бизнес-изменений.

### M6 — Приёмка и передача MVP

Зависимости: M1–M5. Требования: все FR/NFR/UC; U-05. Этапы: тесты, README, документирование и повторный аудит.

- [x] Минимум 25 содержательных JUnit-тестов превышен: выполнены 103 backend core/HTTP и 17 frontend; отдельно 10 launch-тестов.
- [x] Подготовлены 20 PostgreSQL IT и 4 native JavaFX E2E сценария, единый скрипт запуска проверок.
- [x] Документация связана: ТЗ → FR/NFR/UC → milestones → модули/RBAC/DBML → изменения/аудит.
- [x] README содержит запуск, учётные данные, сборку, тесты и ограничения; в Git есть три реальных коммита.
- [ ] Полнота этапной Git-истории удовлетворяет NFR-09; существующие коммиты не заменены выдуманными этапами.
- [ ] Полная сборка и все PostgreSQL/JavaFX/POI проверки проходят без пропусков в доступном окружении.
- [ ] Все 10 экранов ТЗ и их UC приняты сквозным выполнением; ограничения аудита, мешающие приёмке, закрыты.

MVP нельзя считать принятым, пока открыты пункты приёмки M1–M6. Обязательные незавершённые требования не переносятся в POSTMVP ради статуса «готово».

## Фаза 2 — POSTMVP: развитие существующих доменов

Это необязательные улучшения реализации уже существующих требований, **не новые требования ТЗ**. Начало после приёмки M6; новые бизнес-домены требуют отдельного уточнения ТЗ.

### M7 — Работа со списками при расширении данных

Основание: FR-12; UC-03–UC-06. ТЗ допускает разумную загрузку; текущая реализация использует её, серверная пагинация не обязательна для MVP.

- [ ] Домен справочников: при необходимости большого набора заменить полную загрузку серверной пагинацией/фильтрацией, сохранив RBAC и операции карточек.
- [ ] Домен расписания: при такой замене сохранить одинаковые результаты календаря и таблицы.

### M8 — Сопровождение доменных правил

Основание: NFR-02, NFR-05, NFR-08; U-01. Не меняет согласованные функции.

- [ ] Разнести общий UniversityService по сервисам бизнес-доменов без изменения CRUD-контрактов и прав доступа.
- [ ] Сохранить сквозные регрессии доступа, расписания, журналов, аналитики и экспорта после этого изменения.
