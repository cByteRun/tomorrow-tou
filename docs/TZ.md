# ТЗ: Университетская информационная система

## 1. Основные требования

- Тип: полноценное настольное приложение с графическим интерфейсом.
- Стек: Java, JavaFX, Spring Boot, Spring Data JPA/Hibernate, PostgreSQL или MySQL.
- Роли: `ADMIN`, `TEACHER`, `STUDENT`, `STUFF`
- Минимум: 8 полноценных экранов.
- Интерфейс: главное окно, меню, Dashboard, таблицы, формы, поиск, фильтры, диалоги, аналитика.
- Консоль: только технические логи, без пользовательских операций.

## 2. Архитектура и технологии

| Компонент | Требование |
| --- | --- |
| 🎨 GUI | JavaFX, FXML / Scene Builder |
| ⚙️ Backend | Spring Boot, Service Layer |
| 🗄️ ORM | Spring Data JPA / Hibernate |
| 💾 БД | PostgreSQL или MySQL |
| 🧩 Модель | Минимум 8 сущностей, связи 1:N и N:M, ограничения |
| 🛡️ Качество | Валидация, обработка исключений, транзакции |
| 📝 Логи | Log4j 2: `app.log`, `error.log`, аудит |
| 📄 Экспорт | Apache POI: XLSX и DOCX |
| 🧪 Тестирование | JUnit, минимум 25 содержательных тестов |
| 🔀 Git | История разработки по этапам, README |

## 3. Экраны приложения

| № | Экран | Основные функции |
| --- | --- | --- |
| 1 | 🔐 Авторизация | Логин, пароль, переход в интерфейс своей роли |
| 2 | 📊 Dashboard | Статистика, занятия сегодня, средний балл, диаграмма |
| 3 | 🎓 Студенты | Таблица, поиск, фильтры, карточка, CRUD |
| 4 | 👨‍🏫 Преподаватели | Дисциплины, расписание, нагрузка |
| 5 | 👥 Группы | Состав, дисциплины, куратор |
| 6 | 📅 Расписание | Таблица/календарь, проверка конфликтов |
| 7 | ✅ Посещаемость | Отметка присутствия по занятию |
| 8 | 📝 Оценки | Выставление, редактирование, средние показатели |
| 9 | 📑 Отчёты | Excel-ведомость, Word-академическая справка |
| 10 | ⚙️ Профиль/настройки | Данные пользователя, выход из системы |

Примечание: указано 10 экранов, что превышает минимум в 8.

## 4. Сущности базы данных

Обязательные сущности из ТЗ:

`User`, `Student`, `Teacher`, `Group`, `Subject`, `Lesson`, `Attendance`, `Grade`, `Semester`, `Room`.

Требования к модели:

- Минимум 8 сущностей — указанное количество превышает минимум.
- Связи `1:N` и `N:M`.
- Ограничения целостности данных.
- Хранение данных в PostgreSQL docker

## 5. Бизнес-логика

- 🔴 Автоматическое обнаружение конфликтов расписания преподавателя и аудитории.
- 🟠 Расчёт среднего балла студента, группы и дисциплины.
- 🔴 Студент видит только собственные оценки.
- 🔴 Преподаватель видит только свои дисциплины.
- 🟠 Dashboard получает статистику из БД.
- 🟠 Проверка обязательных полей и понятные сообщения об ошибках.
- 🟠 Подтверждение опасных действий: удаление, отмена, списание и другие применимые операции.
- 🟠 Поиск, фильтрация, сортировка и пагинация либо разумная загрузка данных.
- 🟠 Экспорт реальных данных в XLSX и DOCX.

## 6. Визуальные требования

- Единый современный стиль всех экранов.
- Главное окно с боковым или верхним меню.
- Понятная навигация между разделами.
- Таблицы с действиями «Добавить», «Изменить», «Удалить/Отменить».
- Ошибки через `Alert/Dialog` рядом с действием пользователя.
- Минимум 2 визуальных элемента аналитики: графики, диаграммы или KPI-карточки.
- Отсутствие заранее прописанных чисел в Dashboard вместо реальных данных.
